# 授权使用与密钥管理

> 面向**你（授权方/维护者）**的操作手册：怎么签发、怎么激活、**怎么更换密钥**、密钥放哪、出了各种提示怎么办。
> 原理与边界见 `docs/LICENSE_OFFLINE.md`；工具目录见 `tools/license_generator/`。

## 1. 密钥放在哪（**私钥绝不入库、绝不进发布包**）

| 用途 | 位置 | 是否入库 | 是否随包 |
| :--- | :--- | :-: | :-: |
| **工作用私钥** | `tools/license_generator/keys/private_ed25519.pem` | ❌（被 `.gitignore` 排除） | ❌ |
| 工作用公钥 | `tools/license_generator/keys/public_ed25519.pem` | ❌ | ❌ |
| **安全备份（仓库外）** | `%USERPROFILE%\.usb-wiki-license\keys\` | 天然在仓库外 | ❌ |
| **内置公钥（随包）** | `app/core/license_pubkey.py` 的 `PUBLIC_KEY_B64` / `KEY_ID` | ✅（公钥本就要公开） | ✅ |

规则：
- **私钥 = 唯一能伪造激活码的东西**。只在本机、只进加密备份，不以明文走微信/邮件/网盘。
- 本仓库是 **Public**：任何时候都要能证明私钥没被提交 —— 见 §6 自查命令。
- 公钥指纹（`KEY_ID`）用来识别"当前是哪把钥匙在验签"，轮换后一眼可辨。

## 2. 首次：签发一枚激活码

> 用仓库自带运行时跑工具（它自带 `cryptography`，无需装环境）：
> `runtime\python-3.11-embed\python.exe`。**首次需先生成密钥对**（若尚未生成）。

**① 生成密钥对（只做一次）**

```bat
runtime\python-3.11-embed\python.exe tools\license_generator\genkey.py
```

把打印出的两行覆盖进 `app/core/license_pubkey.py`：

```python
PUBLIC_KEY_B64 = "……"
KEY_ID = "……"
```

**② 让客户提供「设备码」**：客户打开 **设置 → 产品授权**，点「复制」，把设备码（形如 `C3285E2A-3A90-A661-…`）发给你。

**③ 签发**

```bat
rem 永久授权
runtime\python-3.11-embed\python.exe tools\license_generator\license_gen.py ^
    --device-code "C3285E2A-3A90-A661-…" --customer-id CUST-0001 --perpetual

rem 到期授权（可带功能位）
runtime\python-3.11-embed\python.exe tools\license_generator\license_gen.py ^
    --device-code "C3285E2A-…" --customer-id CUST-0002 --features pro,sync --expires 2027-09-29
```

**④ 把打印出的激活码发回客户**。全流程离线，之后客户端只用内置公钥验签。

## 3. 客户侧：怎么激活 / 查看 / 清除

设置页 →「产品授权」卡片：

| 动作 | 说明 |
| :--- | :--- |
| 复制设备码 | 发给授权方 |
| 输入激活码 | 粘贴授权方发来的整段码 → 点「激活」 |
| 查看状态 | 徽标显示 已激活 / 未激活 / 异常；含客户号、功能位、有效期、验签公钥指纹 |
| 清除本机激活 | 回到未激活态（不改动资料库与笔记） |

顶栏也有「授权」状态芯片，随状态自动刷新。

## 4. 更换 / 轮换密钥（**重点**）

### 4.1 什么时候要换
- 私钥疑似泄露（最急）；
- 想把密钥换成你自己新生成的一套；
- 产品更名 / 重建发布体系。

### 4.2 步骤（一次到位）
```bat
rem 0) 先备份旧密钥（备份不可省：私钥丢了就再也签不了新码）
copy tools\license_generator\keys  %USERPROFILE%\.usb-wiki-license\keys-backup-%DATE:~0,4%%DATE:~5,2%%DATE:~8,2%  /Y   （或手动整目录复制）

rem 1) 生成新密钥对（--force 才允许覆盖已有私钥）
runtime\python-3.11-embed\python.exe tools\license_generator\genkey.py --force

rem 2) 把打印出的两行覆盖进 app/core/license_pubkey.py（PUBLIC_KEY_B64 / KEY_ID）

rem 3) 重启程序，让新公钥生效（顶栏「授权」会显示异常，因为旧码已不匹配）
```

### 4.3 影响（**不联网，别误会**）

这一层**没有任何联网验证**，客户端不会"回连"授权方。机制如下：

- 客户端**每次启动**都会用**自己内置的公钥**，重新校验本机保存的那份激活码（需求 7）。
- 你在自己这边换私钥，**不影响任何已装客户端** —— 它们内置的还是旧公钥，旧码照验通过。
- 真正失效的时刻，是**客户端拿到内置了新公钥的新版本程序之后**：它再拿**旧私钥签的旧码**去对**新公钥**验签 →
  必然失败 → 界面回到「未激活」，需用新私钥签的码**重新激活**。

| 情形 | 是否受影响 |
| :--- | :--- |
| 客户**继续用旧版本**、不更新 | ❌ 不影响，旧码照常有效（纯离线） |
| 客户**更新到含新公钥的新版本** | ✅ 需重新激活（旧码被新公钥拒，显示「激活码无效或已被篡改。」） |
| 全新客户 | 直接用新私钥签的新码即可 |

> 准确表述：**"换锁芯"本身不吊销任何东西；只有把"新锁芯"装进客户端后，升级过的客户端才认不出旧钥匙。**
> 不升级的老客户端会一直用旧码离线工作 —— 这不是"联网吊销"，离线环境里根本查不到任何"吊销名单"。

### 4.4 只换公钥不换私钥
不行。公钥必须与其对应的私钥配套；单换公钥会让**已签发码与新公钥不匹配**。要么整套换，要么不换。

### 4.5 平滑轮换（可选增强：公钥钥匙串）

当前实现**内置单把公钥**，所以"新公钥上到客户端 → 旧码失效"。若要**轮换又不打扰存量客户**，
可把客户端改为内置**多把可接受公钥**（旧+新），按码里的 `key_id` 或逐个试签：

1. 先发一版**"钥匙串"客户端**（同时接受 旧、新 两把公钥）—— 此版本仍能验旧码，存量客户无感；
2. 等全部客户都升上"钥匙串版"后，新签发的码一律走**新私钥**；
3. 之后再发一版**移除旧公钥**的客户端，此时旧码才真正失效（可控地"分两步吊销"）。

代价：客户端需多存/校验一个 `key_id`，代码略增；收益：轮换不再是一次性"全员重激活"。默认不启用，保持简单。

## 5. 把密钥存到别处（不放在仓库内）

工具默认读 `tools/license_generator/keys/private_ed25519.pem`。要改用别处的私钥，用 `--private` 显式指定：

```bat
runtime\python-3.11-embed\python.exe tools\license_generator\license_gen.py ^
    --private "%USERPROFILE%\.usb-wiki-license\keys\private_ed25519.pem" ^
    --device-code "…" --customer-id CUST-0003 --perpetual
```

本机已把一份密钥副本放在仓库外：`%USERPROFILE%\.usb-wiki-license\keys\`（安全备份）。
**建议**：正式密钥只留仓库外那一份，仓库内 `tools/.../keys/` 仅作开发用；两者若不一致，以你手工指定的 `--private` 为准。

## 6. 安全自查（随时可跑）

```bat
rem A. 私钥绝不能被 Git 跟踪（应为空输出）
git ls-files | findstr /I ".pem .key "

rem B. 确认 keys/ 被忽略
git check-ignore -v tools/license_generator/keys/private_ed25519.pem

rem C. 确认发布产物不含私钥（应 PASS）
runtime\python-3.11-embed\python.exe tests\test_license_offline.py
```

要点：
- 本仓库是 **Public**，一旦 `pem/key` 出现在 `git ls-files` 就要立刻处理（改密钥 + 清历史）。
- 发布物 `dist/` 与客户端 `app/` 都不应含私钥；上面测试 C 会逐项断言。

## 7. 常见提示对照

| 界面提示 | 状态码 | 含义与处理 |
| :--- | :--- | :--- |
| 此激活码不属于当前设备。 | `DEVICE_MISMATCH` | 换机/重装系统/换硬盘导致指纹变。按新设备码**重签**。 |
| 此激活码已过期。 | `EXPIRED` | `expires_at` 已过。重签一张新的。 |
| 激活码无效或已被篡改。 | `BAD_SIGNATURE` | 用了**另一把**公钥签的码（如刚轮换过）；或码被改动。确认真钥配套后重签。 |
| 激活码格式无法识别。 | `MALFORMED` | 粘贴不全/带了多余字符/版本不符。让客户重新整段复制。 |
| 该激活码不属于本产品。 | `PRODUCT_MISMATCH` | 签发时 `--product` 与本客户端不符。 |
| 本机缺少签名校验组件，暂时无法验证授权。 | `CRYPTO_UNAVAILABLE` | 运行环境缺 `cryptography`（应只出现在非正式环境）。 |
| 尚未激活。 | `NO_LICENSE` | 正常未激活态。 |

## 8. 关键提醒

- **设备指纹**由硬件派生（`MachineGuid` + 系统盘卷序列号 + 架构 → SHA-256）：重装系统、换主板/硬盘、改机器名之外的重大变更都可能**改变指纹**，需重签。这是"一机一码"的固有代价。
- 本授权层目前是**软门禁**：默认只呈现状态、不阻断功能。若将来要按授权硬性限制功能，需另行开发（见 `docs/LICENSE_OFFLINE.md` §11）。
- 离线场景**没有实时吊销**：只能靠"轮换密钥 + 重签"来作废旧码。
