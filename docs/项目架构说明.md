## 2. 数据流

### 2.1 知识摄入
```
URL ──► crawler.fetch_html ──► trafilatura 抽取 ──► 字数阈值判定
                                     │                    │
                                     │         ┌──────────┴──────────┐
                                     │         ▼                     ▼
                                     │   ≥150 字                <150 字
                                     │   status: success     status: partial_fallback
                                     │   notes/web_*.md      + snapshots/*.html 快照
                                     └─────────┬─────────────────────┘
                                               ▼
                                    chunker.parse → Parent(800字) + Child(200/30)
                                               ▼
                            indexer.index_parsed → 文档级先清空后写入
                                               ▼
              documents / parent_blocks / chunk_metadata / chunks / chunks_fts / chunks_vec
```

### 2.2 混合检索
```
Query ──► 长度嗅探路由
            ├─ 纯英文数字 ≥3 字符 或 中文 ≥3 字符 ──► FTS5 MATCH (trigram, bm25 排序)
            └─ 更短 / 空结果兜底 ─────────────────────► LIKE '%kw%' 全表扫描
                                                        │
Query ──► embedder.embed ──► chunks_vec KNN (k=20) ─────┤
                                                        ▼
                      RRF 融合 Score(d)=1/(60+rank_fts)+1/(60+rank_vec)
                                                        ▼
                        子切片 → 父分块去重聚合 → Top-5 父分块 + 引用溯源
```

### 2.3 AI 网关
```
provider=auto ──► Ollama 健康缓存(60s TTL)
                    ├─ 有效 ──► /api/chat 流式 ──► SSE delta 帧
                    └─ 失效 ──► api_key 已配置 ──► /chat/completions 流式
                                   └─ 未配置 ──► 纯离线 FTS5 高亮回答
SSE 帧顺序：references（首帧）→ meta → delta* → done
```

## 3. 关键设计决策

| 决策 | 原因 |
| :--- | :--- |
| **服务层用标准库 `http.server`** | 嵌入式 Python 运行时体积敏感；避免 Flask/FastAPI 及其传递依赖，也规避了 WSGI 在 Windows 下的进程模型复杂度 |
| **每连接加载 `sqlite-vec`** | SQLite 可加载扩展是**连接级**状态。早期只在首个连接加载会导致其它线程报 `no such module: vec0` |
| **`chunks_vec` 不做动态行删，改文档级重建** | 规避 `vec0` 虚拟表行级删除的历史边界 Bug；且经实测 `vec0` **不支持 `INSERT OR REPLACE`**，必须显式先删后插 |
| **FTS5 显式先删后插** | 实测 `INSERT OR REPLACE` 在 FTS5 上**不替换而是静默追加重复行**，会污染 bm25 排序 |
| **端口探测不设 `SO_REUSEADDR`** | Windows 上 `SO_REUSEADDR` 语义近似 `SO_REUSEPORT`，会让"端口占用"检测失效并可能抢占他人端口 |
| **onnxruntime 用子进程探针** | `Illegal Instruction` 在 Python 层不可捕获；子进程隔离使 SIGILL 只牺牲探针而非整个系统，探针结果带 7 天磁盘缓存 |
| **`_pth` 显式 `import site`** | 官方 embeddable 包默认屏蔽 `site`，导致 `Lib/site-packages` 不生效 |
| **Batch 文件保持纯 ASCII** | cmd.exe 按当前控制台代码页解析批处理，内嵌中文在 CP936 宿主机上会乱码 |
| **批处理避免括号块内 `%ERRORLEVEL%`** | cmd 对整个括号块在**解析期**展开 `%VAR%`，会捕获到过期的退出码 |

## 4. 数据库 Schema

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;

sys_meta(key PK, value)                       -- 签名守卫 / vec_dim / schema_version
documents(doc_id PK, rel_path UNIQUE, file_size, mtime, title, status, sha1, indexed_at)
chunk_metadata(chunk_id PK, doc_id, parent_id, char_len)   -- FK CASCADE
parent_blocks(parent_id PK, doc_id, content, ord)          -- FK CASCADE
chunks(chunk_id PK, doc_id, parent_id, content)            -- 短词 LIKE 降级用
chunks_fts  USING fts5(chunk_id UNINDEXED, doc_id UNINDEXED, content, tokenize='trigram')
chunks_vec  USING vec0(chunk_id TEXT PRIMARY KEY, embedding FLOAT[512])
```

`documents.sha1` 实际存储**文件前 4KB 的 XXH64/blake2b 哈希**，作为 exFAT 等长编辑的第二指纹。

## 5. 三项隐蔽工程细节的落地位置

| # | 风险 | 落地位置 | 实现 |
| :-: | :--- | :--- | :--- |
| 1 | exFAT 等长编辑漏扫 | `core/sync.py :: NoteSyncer._decide` | 三分支判定：时间明显后移 → 大小变化 → **前 4KB 快速哈希比对**；并新增 `mtime-rewound` 保守重建分支 |
| 2 | Windows 终端编码锁死 | `启动-Windows.bat` 前三行 | `chcp 65001` + `PYTHONIOENCODING=utf-8` + `PYTHONUTF8=1`；批处理本体保持纯 ASCII，中文提示交由 Python 输出 |
| 3 | onnxruntime 指令集崩溃 | `core/embedder.py` | CPU 特性位预检 + **子进程 import 探针** + 顶层 `except BaseException` 三层防护，失败自动切换嵌入源并向前端推送告警 |

## 6. 降级矩阵

| 环节 | 首选 | 降级 1 | 降级 2 | 兜底 |
| :--- | :--- | :--- | :--- | :--- |
| 正文抽取 | trafilatura + lxml | trafilatura bare | stdlib `html.parser` | 快照 + 引导粘贴 |
| 嵌入源 | `local_onnx` | `ollama` | `api` | 纯 Python 哈希向量 → 纯 FTS5 |
| 对话模型 | 本地 Ollama | 云端 API | — | 离线检索高亮摘要 |
| 向量检索 | `sqlite-vec` KNN | — | — | FTS5 单路（RRF 自动退化） |
| 动态页抓取 | Headless Chrome（可选） | — | — | 静态 HTML 直接抽取 |

> 注：`local_hash`（纯 Python 字符 n-gram 哈希向量）是对「降级至纯 FTS5」原始设计的**加强**而非替代 ——
> 在无 onnxruntime、无 Ollama、无 API Key 的极端环境下，仍保留向量召回通道使 RRF 双路融合成立，
> 并由控制台明确告警「召回质量有限」。如需严格按原始设计退化为纯 FTS5，在 `config.ini` 设
> `embedding_source = none` 即可。
