# PILOT_VALIDATION — Digital Pilot 观察指标

> 阶段：**Digital MVP Freeze & Pilot Artifact**（2026-09-18 起）。
> 软件测试通过 ≠ 产品验证成功。本文件只定义**人工观察项**，不做任何遥测/埋点。
> 每位测试者一张记录，人工填写，汇总即 Pilot 结论。

## 0. 背景

- 目标：让真实的人尽快碰到产品，验证「是否有人真正愿意使用」。
- 范围：数字分发的 Windows 安装包（`USB-WIKI-v1.3.0-pilot-win-x64`）。
- 主路径：下载 ZIP → 解压 → 双击安装 → 启动 → 导入资料 → 搜索/语义检索 → 查看引用。
- Chat 是 optional capability，不是 Pilot 成功的硬前提。

## 1. 观察指标（逐位测试者记录）

| # | 指标 | 记录方式 |
|---|------|----------|
| 1 | 能否**独立完成安装**（无人指导） | 是 / 否；卡在哪一步 |
| 2 | 能否**成功导入第一份文件** | 是 / 否；用了三种方式中的哪种 |
| 3 | **多久完成第一次搜索** | 从打开页面起计时（分钟） |
| 4 | 是否**理解搜索结果与引用**（角标→原文） | 能讲清 / 模糊 / 没理解 |
| 5 | **第二次是否还愿意打开** | 是 / 否 |
| 6 | 有没有**主动想导入更多资料** | 是 / 否 |
| 7 | 是否**主动询问 AI 对话功能** | 是 / 否 |
| 8 | 是否**愿意为 Chat 安装额外模型** | 是 / 否 |
| 9 | **是否愿意付费**；大概范围 | 是 / 否；金额区间 |

定性补充：用户的第一句话（打开后说的第一句）；最常停留在哪个标签页。

## 3. 边界（本阶段明确不做）

- ❌ 不做任何 telemetry / 行为分析 SDK / 云端回传 / 用户账户。
- ❌ 不做下载站 / 官网 / CDN —— 产物经 GitHub artifact / Release draft / 网盘人工发送。
- ❌ 不做 onboarding wizard、不重做 UI —— 只修真正阻塞首次体验的问题。
- ❌ 不重开 Physical USB 议题（拔盘 / 容量 / 量产 / 采购 / 包装 / U 盘 RC），保持 POST_PRODUCT_VALIDATION。

## 4. 判定

- Pilot 通过（进入下一步讨论）的最低信号：≥1 位陌生用户**无人指导**独立完成
  「安装→导入→搜索→看懂引用」主路径，且表示会继续用。
- 没人第二次打开 = 产品问题优先于功能问题，回到 #8 首次体验检查。
