## L1 · 责任归属只识别「由 X 负责」句式，其余句式会被误判为"无关系证据"（建议发布前修）

- **现象**：`谁负责数据平差与报表编制？` 被判 `INSUFFICIENT_RELATION` → `allow_relation_claim=false`
  → 用户拿到"没有找到直接关系证据"，而资料里明明写着「数据处理员：**李岚，负责**数据平差与报表编制」。
- **根因**：`relation_guard` 的责任分支用正则 `由(.+?)负责` 提取责任方。语料里用的是
  「XX，负责…」/「负责人：XX」/「责任人为 XX」这类常见写法，**不含"由…负责"**，于是提取不到责任方，
  一路落到 STRONG 判定（该题 target 为空）→ INSUFFICIENT。
- **影响面**：Holdout B 中 1/57（普通题 1/44 = 2.3%）。**但这是句式覆盖问题，不是个案** ——
  真实中文技术文档里「由 X 负责」只是多种责任写法之一，实际语料中的触发率可能显著高于 2.3%。
- **为什么不算 Blocker**：规格的 D 是「**大面积**误拦」；本例 1 例、根因明确，且失败是**拒答**
  （安全方向），不是给出错误答案。
- **建议**：扩展责任方提取句式（「XX 负责…」「负责人：XX」「责任人为 XX」「由 XX 负责」），
  并补充对应 gold 后重跑；**不要**为此修改 Holdout B 的 gold/fixture。

## L2 · 阻断文案是「因果」形状的，责任类读起来别扭（文案层，非逻辑层）

- **现象**：`水库调度是否由排水管理处负责？` → 输出
  「把「排水管理处」归因于「防汛指挥部」……」。语义上系统**正确地拒绝**了（真责任方是防汛指挥部），
  但句子把「排水管理处」（被质疑的责任方）当成了"被归因的对象"，读起来像是在说
  "排水管理处属于防汛指挥部"，不准确。
- **建议**：`blocked_message()` 按 `relation_type` 分流模板；causal 用现文案，
  responsibility 改成「「{anchor}」的责任方是「{owner}」，不是「{target}」」。

## L3 · table_relation 的 Recall@1 为 80%（长尾问法）

- 5 题里 1 题 Top1 未命中（`2号主变的投运日期是什么？`），Recall@3/5 仍为 100%。
- 属于"Top1 排名不理想"，按规格为 NON-BLOCKER。

## L4 · Citation overlap 98.1%（1 题未相交）

- 逐条引用口径为 55.6%（**诊断值，天然偏低**：一题返回 5 条引用，其中只有部分是 gold 证据，
  不能拿它当 Gate 判据）。主口径「每题至少一条引用与 gold 区间相交」= 98.1%。
- 结构合法率 **100%**（125 条引用的 doc_id/parent_id/range 全部合法且归属正确）。

## L5 · LLM smoke 运行时 provider = offline

- 运行时刻本机没有可用的对话模型，PASS / YES 类走的是**离线原文摘录**兜底，
  因此**语言风格、答案组织质量未被评估**。已验证的是：路由、Guard 状态、citation 保留、blocked 不调用 LLM。
- 建议进入 Pilot 前，在**有模型的机器上**重跑一次 smoke 看生成质量。

## L6 · Holdout B 是合成语料（8 篇 / 57 题）

- 语料为人工构造（地铁基坑 / 变电站 / 汛情 / 体检中心 / 软件发布 / 仓储 / 桥梁 / 试验室），
  用于**结构与归因正确性**的验收，不等于真实用户语料的分布。真实资料可能带来新的长尾问法。
- 按规格：**B 只能用一次**。若修复后需要再验收，应新建 Holdout C。
